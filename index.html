AI-Based Road Hazard Detection

A system that lets the public report road damage from their phone, uses AI to check the report, and passes confirmed hazards to the people who fix them.

83.28%mAP@0.5 on validation (target was 70%)
8,540labelled road images, up from 4,318
2detection classes: pothole and crack, with crack subtypes like alligator and longitudinal
SilverPIXEL 2026 innovation showcase

Problem

Road damage in Malaysia is found through slow manual inspections and scattered public complaints. Every report has to be checked by hand before repairs are scheduled, so hazards stay on the road for longer than they should.

What I built

  • A YOLOv8 detector trained on local road images, with a custom "tropical augmentation" step that simulates monsoon rain, tree shadows and puddle glare.
  • A React PWA so anyone can report a hazard with a photo and GPS location, no sign-up needed.
  • An admin dashboard where the AI's detections are confirmed or corrected. Corrections feed a retraining loop (human in the loop) that only promotes a new model if it improves.
  • A contractor portal so verified hazards go straight to the team that repairs them.

Sightline

An interactive heatmap of where Valorant players stand, die and get kills on every competitive map, built from 1,358 ranked matches for players who want to learn common positions by rank.

Why I built it

When I peek a site, where is the enemy most likely to be? I wanted to answer that with real match data instead of gut feel, and see how my friends and I compare to Immortal and Radiant players.

How it works

  • Match data comes from the HenrikDev API (an unofficial Riot data source), with minimaps, callouts and agent icons from valorant-api.com.
  • Each kill records where all ten players were standing. Python scripts convert those game coordinates onto the minimap, bin them into a 48x48 grid and blur them into density heatmaps, labelled with the nearest callout.
  • Filter by map, rank (Iron to Radiant), side, round phase, agent class, agent or individual player, and switch between positions, deaths and kills. A round-timing chart shows when fights happen.

Technical assessment · 2026

Product Catalog App

A mobile product catalog built in Flutter as a technical assessment for a job application, time-boxed to roughly 2 to 3 hours.

The brief

Build a small product catalog app that lists products from a public REST API, lets users tap into a product for full details, and includes basic search. The app needed to handle loading, empty and error states clearly, support pagination as the user scrolls, and be organised into clear code layers rather than one flat file.

What I did

  • A product list with thumbnail, title and price, infinite scroll pagination and pull-to-refresh. A detail screen with full description, price, rating and a swipeable image gallery. A debounced search bar.
  • Data comes from the DummyJSON REST API, fetched over HTTP and parsed into typed Dart models.
  • A sealed-class state pattern (Loading, Empty, Loaded, Error) with a Provider-based state manager, so the UI is always in exactly one well-defined state instead of juggling boolean flags that could contradict each other.
